00 · PrerequisitesBefore you start

There is nothing to install. The simulator is one HTML file with the sample CSV files built in. It fakes a SnowSQL terminal, a local folder and a Snowflake worksheet in your browser.

1
Open the file

Double-click SnowSQL_Streams_Tasks_Lab_Simulator_FINAL.html. It runs offline in Chrome, Edge, Firefox or Safari.

2
Use a wide window

At least 1100 px wide so the terminal (left) and worksheet (right) sit side by side.

3
Know the story

RetailPulse, a made-up retailer, exports inventory CSVs from a local folder. You PUT them to a stage, COPY them in, track changes with streams and automate the merge with tasks.

4
Budget about 58 min

You can stop at any time. Progress saves in your browser for the same file in the same browser.

5
Terminal vs worksheet

Every snippet in this guide carries a label: Terminal (SnowSQL) or Worksheet. PUT only works in the terminal and only after snowsql has connected.

6
Run in order

Steps depend on each other (stream offsets, load metadata). Do them top to bottom. Expected outputs below come from running every step in order on a fresh state.

Values that differ on your screenTimestamps, query IDs, METADATA$ROW_ID, md5 values and task ids change on every run. Counts, states (SUCCEEDED / SKIPPED), prices and quantities must match what is shown here.

Your first Task

Create TSK_MERGE_INVENTORY (every 5 minutes, only WHEN the stream has data), resume it, EXECUTE it and read TASK_HISTORY.

Worksheet~5 min
WHY Stream + Task + MERGE is Snowflake's native incremental pipeline. The WHEN clause means the warehouse is only woken when there is work.
WorksheetCreate task
CREATE OR REPLACE TASK ANALYTICS.TSK_MERGE_INVENTORY
  WAREHOUSE = LAB_WH
  SCHEDULE = '5 MINUTE'
  WHEN SYSTEM$STREAM_HAS_DATA('STAGING.STRM_INVENTORY_RAW')
AS
MERGE INTO ANALYTICS.INVENTORY t
USING (
  SELECT
    product_id::VARCHAR                  AS product_id,
    sku::VARCHAR                         AS sku,
    name::VARCHAR                        AS name,
    category::VARCHAR                    AS category,
    quantity_on_hand::NUMBER             AS quantity_on_hand,
    unit_cost::NUMBER(10,2)              AS unit_cost,
    unit_price::NUMBER(10,2)             AS unit_price,
    warehouse_id::VARCHAR                AS warehouse_id,
    last_updated::TIMESTAMP_NTZ          AS last_updated,
    status::VARCHAR                      AS status
  FROM STAGING.STRM_INVENTORY_RAW
  WHERE METADATA$ACTION = 'INSERT'
  QUALIFY ROW_NUMBER() OVER (PARTITION BY product_id ORDER BY last_updated DESC) = 1
) s
ON t.product_id = s.product_id
WHEN MATCHED THEN UPDATE SET
  t.sku = s.sku, t.name = s.name, t.category = s.category,
  t.quantity_on_hand = s.quantity_on_hand, t.unit_cost = s.unit_cost, t.unit_price = s.unit_price,
  t.warehouse_id = s.warehouse_id, t.last_updated = s.last_updated, t.status = s.status
WHEN NOT MATCHED THEN INSERT
  (product_id, sku, name, category, quantity_on_hand, unit_cost, unit_price, warehouse_id, last_updated, status)
VALUES
  (s.product_id, s.sku, s.name, s.category, s.quantity_on_hand, s.unit_cost, s.unit_price, s.warehouse_id, s.last_updated, s.status);

06 · HelpTroubleshooting

I ran the SQL but the checks stay grey.
You probably pressed Ctrl/⌘+Enter, which runs only the statement under the cursor. Use Ctrl/⌘+Shift+Enter. Check that the context bar says LAB_ANALYST · LAB_WH · RETAILPULSE_LAB; if not, re-run step 1 (or the USE lines).
PUT says it is not supported in the web interface.
You ran it in the worksheet. Use the Terminal tab, and connect first with snowsql -a myaccount.us-east-1 -u lab_user.
The terminal says "Connect first".
You typed SQL or a PUT before snowsql connected. Run the connect line and type any password.
COPY says "0 files processed".
Load metadata remembers the file (name + md5) for 64 days. That is the desired result on a re-run in step 5. If you need to reload on purpose, truncate the table (which clears the metadata) or use FORCE = TRUE and accept duplicates.
The stream is empty when I expected rows.
Streams only show changes made after they were created, and a committed DML that reads them (MERGE, INSERT...SELECT) moves the offset. Check the order in the data table above; if you consumed S or A too early, Reset and redo the steps in order.
"Unable to update graph with root task ... not suspended".
Expected in step 12 snippet 1. Otherwise suspend the root, change the graph, resume the children, then the root.
INVENTORY is not 37 after step 11.
The standard stream S was consumed by something other than the MERGE, or step 9 was skipped. Reset and redo from step 7; only the MERGE (step 8, then the task) may read S.
Snapshot count is double the inventory count.
The -f nightly_rollup.sql run happened twice. Recreate the snapshot table (step 13 snippet 1) and run the file once.
My progress disappeared.
Progress is stored per browser and per file location. A different browser, a private window or a moved file starts fresh. Ticks in this guide are stored separately in your browser.
Is this real Snowflake?
No. It is a JavaScript engine built to behave like Snowflake for this lab's statements, with realistic error messages. A few details are simplified (for example the simulator accepts MATCH_BY_COLUMN_NAME on CSV without PARSE_HEADER and prints a heads-up). The same SQL runs on a real trial account.

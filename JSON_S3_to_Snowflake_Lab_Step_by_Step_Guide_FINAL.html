00 · PrerequisitesBefore you start

There is nothing to install. The simulator is one HTML file with the sample data built in. It fakes the AWS console and a Snowflake worksheet entirely in your browser.

1
Open the file

Double-click JSON_S3_to_Snowflake_Lab_Simulator_FINAL.html. It opens in Chrome, Edge, Firefox or Safari and runs offline. With internet you also get the nicer fonts.

2
Use a wide window

Use a laptop or desktop at least 1100 px wide so AWS and Snowflake sit side by side. Narrower windows stack the panels.

3
Know the story

ShopStream, a made-up online store, drops order JSON into S3. Your job: get it into Snowflake, clean it, and keep it updated automatically.

4
Budget about 63 min

You can stop at any time. Progress saves in your browser and comes back when you reopen the same file in the same browser.

5
Read before you run

Every Insert SQL button drops real Snowflake SQL into the editor. Read it first; that is where the learning happens.

6
Optional warm-up

Skim the Visual Guide first for the big picture. Afterwards, drill the Interview Q&A.

01

Set up the environment

Create the role, warehouse, database and the RAW + CURATED schemas, then point your session at them.

Worksheet~3 min

▶Do this

  1. Click the step pill 1 Setup in the mission bar (it is selected on first open).
  2. Click Insert SQL: Setup script. The SQL appears in the editor.
  3. Read it top to bottom, then press Ctrl/⌘+Shift+Enter (or click ▶▶ Run all).

✓Green checks the simulator waits for

  • Role, warehouse, database, RAW + CURATED exist
  • Session context is LAB_ENGINEER / LAB_WH / SHOPSTREAM_LAB

◉You should see

  • One results tab per statement, each with a green success message.
  • The context bar above the editor changes to LAB_ENGINEER · LAB_WH · SHOPSTREAM_LAB.RAW.
  • The Objects browser on the left of the worksheet now shows SHOPSTREAM_LAB with RAW and CURATED.
Try the mistakePress Ctrl/⌘+Enter instead of Run all: only the line under the cursor runs, and the checks stay grey. Run all fixes it.
Say it in the interview"First I set up a role, an XSMALL auto-suspending warehouse, and a database with a RAW schema for landed data and a CURATED schema for clean tables."
02

Create the storage integration

Create S3_LANDING_INT, the keyless link that lets Snowflake assume an AWS IAM role.

Worksheet~3 min

▶Do this

  1. Optional, try the error first: type CREATE STORAGE INTEGRATION X TYPE=EXTERNAL_STAGE STORAGE_PROVIDER='S3' ENABLED=TRUE STORAGE_AWS_ROLE_ARN='arn:aws:iam::111122223333:role/snowflake-s3-access-role' STORAGE_ALLOWED_LOCATIONS=('s3://shopstream-raw-landing/landing/'); and press Ctrl/⌘+Enter while you are still LAB_ENGINEER.
  2. Click Insert SQL: Create integration and press Ctrl/⌘+Shift+Enter.

✓Green checks the simulator waits for

  • S3_LANDING_INT exists with the lab IAM role ARN
  • Allowed location covers s3://shopstream-raw-landing/landing/

◉You should see

  • The optional attempt fails with a real Insufficient privileges error: only ACCOUNTADMIN can create integrations.
  • The script switches to ACCOUNTADMIN, creates the integration, grants usage, and switches back to LAB_ENGINEER.
  • The left panel badge still says IAM: not trusted. That is expected; step 3 fixes it.
Try the mistakeAvoid CREATE OR REPLACE on the integration later: it generates a new external ID and breaks the trust policy (the badge turns "external ID stale").
Say it in the interview"I use a storage integration, not access keys. It stores the IAM role ARN and the allowed S3 paths."

  2. Click Insert SQL: ABORT_STATEMENT and press Ctrl/⌘+Enter.
  3. Click Insert SQL: CONTINUE and press Ctrl/⌘+Enter.

✓Green checks the simulator waits for

  • Dry run returned the 2 parse errors
  • Saw ON_ERROR = ABORT_STATEMENT fail
  • ON_ERROR = CONTINUE loaded 9 of 11 rows
  • Captured rejects with VALIDATE()

◉You should see

  • Dry run: 2 parse errors (lines 3 and 7), and nothing is loaded.
  • ABORT_STATEMENT: the statement fails on the first bad line, and nothing is loaded.
  • CONTINUE: status PARTIALLY_LOADED, 11 parsed, 9 loaded.
  • VALIDATE(): RAW.ORDERS_LOAD_ERRORS holds the 2 rejected lines with error text.
Try the mistakeDo the snippets in order. Run CONTINUE before ABORT and the file is already loaded, so ABORT reports "0 files processed". Also try VALIDATION_MODE on the transforming COPY into ORDERS_RAW: Snowflake rejects it, which is why the lab uses a one-column probe table.

05 · HelpTroubleshooting

I ran the SQL but the checks stay grey.
You probably pressed Ctrl/⌘+Enter, which runs only the statement under the cursor. Press Ctrl/⌘+Shift+Enter. Also check that the context bar says LAB_ENGINEER · LAB_WH · SHOPSTREAM_LAB; if not, re-run step 1.
I get "No active warehouse selected" or "does not exist or not authorized".
Your session context was lost or an earlier step was skipped. Run USE ROLE LAB_ENGINEER; USE WAREHOUSE LAB_WH; USE DATABASE SHOPSTREAM_LAB; USE SCHEMA RAW; and check that the earlier pills show ✓.
LIST fails with AccessDenied / sts:AssumeRole.
The IAM trust isn't set. Go to step 3: run DESC INTEGRATION S3_LANDING_INT;, open the IAM role tab and click Update trust policy. If the badge says "external ID stale", the integration was re-created: DESC again, then update again.
The "Paste notification_channel" button is greyed out.
It unlocks only after the AUTO_INGEST pipe exists and you have run SHOW PIPES;. Run the "Stream + pipe" snippet with Run all.
Upload said "Snowpipe was not notified".
The event notification wasn't saved, or doesn't match the pipe's queue. Save it in Event notifications, then run ALTER PIPE RAW.PIPE_ORDERS_INCREMENTAL REFRESH; to load the files already in S3.
The stream is empty after the upload.
Streams only capture changes made after they are created. If you uploaded before creating the stream, click Reset and redo the steps in order, or keep going: the curated tables still work, but step 14's checks need stream rows.
Step 11: ABORT_STATEMENT says "0 files processed".
You ran CONTINUE first, so the file is already recorded as loaded. Run the snippets top to bottom. To redo the step, DELETE FROM RAW.ORDERS_RAW WHERE src_file LIKE 'orders_bad/%'; and add FORCE = TRUE once.
My progress disappeared.
Progress is stored per browser and per file location. A different browser, a private window, or a moved file starts fresh. Ticks in this guide are stored separately, also in your browser.
Is this real Snowflake?
No. It is a JavaScript engine built to behave like Snowflake for this lab's SQL, with realistic error messages. The real SQL scripts in the kit run on a Snowflake trial account; see below.
